Requirement traceability — all services

Pick a service above to upload its PRD and review the matrix. Tickets follow the Service field chosen in the filter bar.

Upload the PRD as Word (.docx), PDF, Markdown or text, or read it straight from Confluence (uses your Jira login; the page must be on the same Atlassian site).

How the PRD maps to Jira

① each PRD requirement belongs to a PRD feature → ② that PRD feature is mapped to a Jira feature (× to remove, or pick the right one) → ③ the user stories under that Jira feature → ④ how many of the feature's requirements have a user story. Click a number to see those requirements.

A requirement is covered when a user story is linked to it. To link one, type or pick the story key under User stories and press Enter (or ✓ a possible match). Use Status to mark it partially covered, not covered, external or out of scope, and Comment to say why.

1. Connect to Jira

Create a token at id.atlassian.com → Security → API tokens. For Jira Server/Data Center leave email empty and paste a Personal Access Token. The token is stored only on this computer (config.json, owner-read-only).

3. Board setup — buckets and statuses

Buckets group your Jira statuses into the stages you report on — e.g. Product = Draft, PM Review, Ready for Refinement; Development = Ready for Development, In Development, Peer Review; QA = Ready for Test, In Testing. Untick Show for statuses you don't want on the board: their tickets are left out of every screen and the Excel file. Applying this doesn't need Jira — it re-labels the data you already have.
